# ورودی طبیعی

با `naturalInput: true` فیلد علاوه بر رقم‌هایی که از ماسک می‌گذرند، متن آزاد را هم می‌پذیرد؛ پس کاربر می‌تواند تاریخ را همان‌طور بنویسد که به زبان می‌آورد: `فردا`، `۳ روز بعد`، `جمعه بعد`، `next friday`، `in 2 weeks`، `+3`. این صفحه توضیح می‌دهد پارسر چه عبارت‌هایی را می‌فهمد، از چه قاعده‌هایی پیروی می‌کند و چطور از کد به کارش ببرید.

## روشن‌کردن {#turning-it-on}

```js
import { createDatePicker } from 'khorshid'

createDatePicker('#due', { locale: 'fa-IR', naturalInput: true })
```

## رفتار فیلد {#how-it-behaves}

- تا وقتی کاربر کلمه تایپ می‌کند، متن دقیقاً همان‌طور که نوشته شده باقی می‌ماند. ورودی‌ای که
  فقط از رقم تشکیل شده باشد، مثل قبل از [ماسک هوشمند](./input-mask) می‌گذرد.
- متن با **Enter** یا هنگام **blur** ثبت می‌شود. اگر تاریخ معتبر باشد، فیلد شکل نرمال‌شدهٔ آن
  را نشان می‌دهد (`فردا` ← `۱۴۰۵/۰۱/۱۶`).
- عبارتی که تاریخ نیست، یا تاریخی که خارج از محدوده یا غیرفعال است، **در فیلد باقی می‌ماند**،
  کلاس `.sdp-input--invalid` می‌گیرد و validity بومی فیلد روی `labels.invalidDate` لوکال
  (`تاریخ معتبر نیست`) تنظیم می‌شود؛ در نتیجه فرمی که فیلد داخلش است ارسال نمی‌شود.
- فیلد `dir="auto"` می‌گیرد و `inputmode` ندارد؛ پس برای نوشتن کلمه، کیبورد کامل باز می‌شود و
  جهت متن هم درست تشخیص داده می‌شود. فیلد در همهٔ حالت‌ها، از جمله range و multiple، قابل
  ویرایش می‌ماند (با [واحد](./selection-units) پیش‌فرضِ روز).

## چه عبارت‌هایی را می‌فهمد {#what-it-understands}

فارسی و انگلیسی **مستقل از لوکال فعال** فهمیده می‌شوند و حتی می‌توانند با هم قاطی شوند
(`۳ days بعد`). همهٔ انواع رقم کار می‌کنند (۳، ٣، 3) و املاهای رایج هم پذیرفته می‌شوند:
`پس‌فردا` / `پس فردا` / `پسفردا`، «ي» و «ك» عربی، و `؟` یا `.` در انتهای عبارت.

| نوع | فارسی | انگلیسی |
|---|---|---|
| روزهای نسبی | `امروز` · `فردا` · `پس‌فردا` · `دیروز` · `پریروز` | `today` · `tomorrow` · `day after tomorrow` · `yesterday` |
| فاصله از امروز | `۳ روز بعد` · `دو هفته دیگه` · `یه ماه بعد` · `۵ روز پیش` | `in 3 days` · `3 days from now` · `5 days ago` · `in a week` |
| فاصلهٔ کوتاه‌نویسی‌شده | `+۳` · `-۲` | `+3` · `-2` · `+2d` · `+2w` · `+1m` · `+1y` |
| دورهٔ بعد / قبل | `هفته بعد` · `ماه قبل` · `سال بعد` | `next week` · `last month` · `next year` |
| روزهای هفته | `جمعه` · `جمعه بعد` · `شنبه گذشته` | `friday` · `next friday` · `last monday` |
| ابتدا و انتهای دوره | `اول ماه` · `آخر سال` · `اول هفته بعد` | `start of month` · `end of next month` |
| روز + ماه | `۱۵ مهر` · `۲۰ اسفند ۱۴۰۴` · `اول اردیبهشت` | `15 March` · `March 15, 2026` · `1st of May` |
| عددی | `۱۴۰۵/۰۱/۱۵` · `1405-1-15` | `2026-04-04` |

### تصمیم‌هایی که پارسر می‌گیرد {#decisions-the-parser-makes}

بعضی عبارت‌ها چندپهلو هستند. پارسر آن‌ها را با این قاعده‌ها حل می‌کند که می‌توانید برای
کاربرانتان هم توضیح دهید:

- **روز هفته به‌تنهایی یعنی امروز یا نزدیک‌ترین روز بعدی، هیچ‌وقت گذشته.** اگر امروز شنبه باشد،
  `شنبه` همین امروز است و `جمعه` شش روز بعد.
- **`next friday` / `جمعه بعد` یعنی جمعهٔ هفتهٔ بعد**، که «هفته» در آن بر اساس `weekStart`
  تعیین می‌شود. بنابراین ممکن است بین ۷ تا ۱۳ روز دیگر باشد. `last friday` / `جمعه قبل`
  نزدیک‌ترین جمعه‌ای است که پیش از امروز بوده (خودِ امروز حساب نمی‌شود).
- **فاصله‌های هفته‌ای دقیق‌اند** (`هفته بعد` یعنی ۷ روز بعد). **فاصله‌های ماهانه و سالانه با
  حساب تقویمی محاسبه می‌شوند و روز را به آخرین روز معتبر ماه محدود می‌کنند**: ۳۱ شهریور به‌علاوهٔ
  یک ماه می‌شود ۳۰ مهر.
- **نام ماه‌ها از مرز تقویم‌ها عبور نمی‌کنند.** در پیکر جلالی `15 March` تاریخ به حساب
  نمی‌آید و در پیکر میلادی `۱۵ فروردین` هم همین‌طور. هر نام ماه فقط در تقویمی خوانده می‌شود که
  به آن تعلق دارد. نام‌های همهٔ لوکال‌های ثبت‌شده روی تقویم فعال پذیرفته می‌شوند؛ پس
  `۱۵ حمل` (دری) هم در پیکر جلالی کار می‌کند.
- **تاریخ عددی باید به شکل `YYYY/MM/DD` باشد**: اول سال چهاررقمی، با هر جداکننده‌ای، و در
  تقویم **فعال** خوانده می‌شود (`1405/01/15` در جلالی و `2026-04-04` در میلادی). شکل‌هایی که
  سال ندارند یا سال را در آخر می‌آورند، مثل `15/01/1405`، چندپهلو هستند و رد می‌شوند.
- **روز نامعتبر اصلاح نمی‌شود**: `۳۱ مهر` (مهر ۳۰ روز دارد) به‌جای اینکه بی‌سروصدا به روز ۳۰
  تبدیل شود، رد می‌شود.
- **سال باید با رقم نوشته شود.** عددهایی که با حروف نوشته می‌شوند (`یک` تا `دوازده`، `one` تا
  `twelve`) فقط به‌عنوان روز یا مقدار فاصله شمرده می‌شوند.
- **یک کلمهٔ ناشناخته کل عبارت را نامعتبر می‌کند.** جمله‌ای که فقط *شامل* یک کلمهٔ تاریخی باشد
  (`فردا سلام`، `tomorrow please`) تاریخ به حساب نمی‌آید.

## بازه در یک خط {#ranges-in-one-line}

در حالت range، فیلد هر دو سر بازه را یک‌جا می‌پذیرد؛ کافی است آن‌ها را با `تا`، `to`، `until`
یا یک خط تیرهٔ فاصله‌دار از هم جدا کنید:

```js
createDatePicker('#trip', { locale: 'fa-IR', mode: 'range', naturalInput: true })
// بنویسید:  امروز تا ۳ روز بعد     →  1405/01/15 – 1405/01/18
// یا:       next friday to +2w
```

<Demo mode="range" :options="{ naturalInput: true }" placeholder="امروز تا جمعه بعد" :controls="['value', 'form']" caption="حالت range با naturalInput: عبارتی مثل «الف تا ب» بنویسید و Enter بزنید." />

هر دو سر بازه با `min` / `max`، `disabledDates` و
[`minDays` / `maxDays`](./shortcuts-and-limits#range-length-mindays-maxdays) سنجیده می‌شوند.
بازه‌ای که محدودیت طول را رعایت نکند، با `error` و کد `'range-length'` رد می‌شود.

## `submitInput()`: همین کار، از طریق کد {#submitinput-the-same-thing-programmatically}

فیلد متن را از طریق یک متد هسته ثبت می‌کند که خودتان هم می‌توانید صدایش بزنید؛ مثلاً با متنی
از یک ورودی به سبک چت یا خروجی تشخیص گفتار:

```js
picker.core.submitInput('پس‌فردا')   // → true، مقدار ثبت شد (change با source برابر 'input')
picker.core.submitInput('blah')      // → false، رویداد error { code: 'invalid-input' } صادر می‌شود
```

متد `submitInput` اول متن را با قالب نمایشی امتحان می‌کند و بعد (اگر `naturalInput` روشن باشد) به‌عنوان
زبان طبیعی. اگر مقداری ثبت شود `true` برمی‌گرداند، و اگر متن را رد کند رویداد `error`
(`invalid-input`، `out-of-range`، `disabled`، `range-length`) صادر می‌کند. بدون `naturalInput` هم
متنی را که در قالب نمایشی باشد می‌پذیرد، که برای مقدارهای paste‌شده به کار می‌آید.

## `parseNaturalDate()`: خودِ پارسر، به‌تنهایی {#parsenaturaldate-the-parser-on-its-own}

پارسر به‌صورت یک تابع کمکی خالص export شده و برای استفاده از آن به پیکر نیازی نیست:

```js
import { parseNaturalDate, PlainDate, getLocale } from 'khorshid/headless'

const today = PlainDate.today('jalali')

parseNaturalDate('۳ روز بعد', { locale: getLocale('fa-IR'), today })
// → یک PlainDate (جلالی)، یا null اگر متن تاریخ نباشد

parseNaturalDate('next friday', {
  locale: getLocale('en-US-gregorian'),
  today: PlainDate.today('gregorian'),
  weekStart: 1, // اختیاری؛ پیش‌فرض: locale.weekStart
})
```

مقدار `today` از بیرون داده می‌شود (و تقویم نتیجه را هم همان تعیین می‌کند)؛ بنابراین خروجی قطعی است
و تست‌کردنش ساده. این تابع هیچ‌وقت خطا نمی‌دهد: برای هر چیزی که نتواند بخواند، `null` برمی‌گرداند.
